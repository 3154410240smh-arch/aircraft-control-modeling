# Workflow architecture

SKILL.md keeps task routing, G0/G1, operation authority and stop/recovery rules. references/engineering.md holds plant/control and architecture/layout rules; verification.md holds observability, event-aware numerical and delivery gates; local-toolchain.md resolves specialist Skills and dynamic schemas; runtime-diagnostics.md is loaded conditionally. agents/openai.yaml supplies UI metadata, not permission.

New models choose real functional boundaries and Direct/Goto-From/Bus representations before building. Direct remains preferred for causal main/feedback relationships. Native blocks handle basic math, limits and physical states; MATLAB Function is evaluated for explicit matrix/branching algorithms with fixed interfaces, types, parameters, timing and independent numerical oracles. Internal subsystem layout is preferred; any root autolayout is only a candidate, not a position lock.

Read actual state after edits. Local scope/incremental mode does not guarantee local geometric effects. Partial, unknown or failed safety results stop dependent writes. Existing-model representation conversions remain restricted unless influence and verification are controlled or explicitly authorized at region level.

Separate structure, normalized per-consumer geometry, original Points/branch records, native visual review, compile/numerical validation, save/reload and independent file/dependency recovery. A successful tool return, image, or compiler cannot replace those independent gates. Never infer a native capability certificate from Skill registration.
